## 一、后端技术知识点

### 1.1 Servlet 与 HTTP 请求处理

#### 1.1.1 HttpServlet 请求分发机制

**核心原理：**

Tomcat 服务器接收到 HTTP 请求后，会根据以下规则自动分发请求：

```
HTTP 请求 → Tomcat → URL 匹配 Servlet → HTTP 方法匹配 doXxx 方法
```

**具体流程：**

```java
// 当浏览器发送 PUT 请求到 /api/cart/789 时
axios.put('/VibeShop/api/cart/789', {quantity: 5})

// Tomcat 会自动：
// 1. 根据 URL 匹配到 CartServlet (@WebServlet("/api/cart/*"))
// 2. 根据 HTTP 方法 PUT，自动调用 doPut() 方法
```

**代码示例（CartServlet.java）：**

```java
@WebServlet("/api/cart/*")  // URL 映射注解
public class CartServlet extends HttpServlet {
    
    // Tomcat 根据 HTTP 方法自动调用对应的 doXxx 方法
    
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) {
        // 处理 GET 请求 - 查询购物车
    }
    
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response) {
        // 处理 POST 请求 - 添加商品到购物车
    }
    
    @Override
    protected void doPut(HttpServletRequest request, HttpServletResponse response) {
        // 处理 PUT 请求 - 更新购物车商品数量
    }
    
    @Override
    protected void doDelete(HttpServletRequest request, HttpServletResponse response) {
        // 处理 DELETE 请求 - 删除购物车商品
    }
}
```

**四种 HTTP 方法对应的操作：**

| HTTP 方法 | CRUD 操作    | 幂等性   | 请求体  |
| ------- | ---------- | ----- | ---- |
| GET     | 查询（Read）   | ✅ 幂等  | 无    |
| POST    | 创建（Create） | ❌ 非幂等 | JSON |
| PUT     | 更新（Update） | ✅ 幂等  | JSON |
| DELETE  | 删除（Delete） | ✅ 幂等  | 无    |

### 1.2 RESTful API 设计

#### 1.2.1 RESTful API 概念

**定义：**

RESTful API 是一种设计风格，基于 HTTP 协议，使用 URL 表示资源，使用 HTTP 方法表示操作。

**与 RPC 风格的区别：**

| 方面        | RESTful API          | RPC 风格                  |
| --------- | -------------------- | ----------------------- |
| URL 设计    | `/api/products` (资源) | `/api/getProducts` (动作) |
| 语义清晰度     | ✅ 清晰                 | ❌ 模糊                    |
| HTTP 方法利用 | ✅ 充分利用               | ❌ 不使用                   |
| 可扩展性      | ✅ 好                  | ❌ 一般                    |

#### 1.2.2 RESTful URL 设计规范

**资源命名规则：**

```
# 复数形式表示集合
/api/products          # 商品列表
/api/users            # 用户列表

# 单数表示单个资源
/api/products/1       # ID 为 1 的商品
/api/users/138        # 手机号为 138 的用户

# 嵌套资源
/api/users/1/addresses  # 用户 1 的所有地址
/api/cart/1/items      # 购物车 1 的所有商品
```

**HTTP 方法映射：**

```
GET    /api/products       → 查询所有商品
GET    /api/products/1    → 查询 ID=1 的商品
POST   /api/products       → 创建新商品
PUT    /api/products/1    → 更新 ID=1 的商品
DELETE /api/products/1    → 删除 ID=1 的商品
```

### 1.3 三层架构

#### 1.3.1 三层架构概述

**定义：**

三层架构将应用分为表示层、业务逻辑层和数据访问层，实现关注点分离。

```
┌─────────────────────────────────────────┐
│         表示层 (Presentation Layer)       │
│   Servlet (控制层)                       │
│   - 接收请求、参数验证                    │
│   - 调用 Service                         │
│   - 返回响应                             │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│         业务逻辑层 (Business Layer)        │
│   Service (服务层)                       │
│   - 业务逻辑处理                         │
│   - 事务管理                             │
│   - 调用多个 DAO                        │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│         数据访问层 (Data Access Layer)    │
│   DAO (数据访问对象)                      │
│   - SQL 语句执行                         │
│   - 结果集处理                           │
│   - 数据库连接管理                       │
└─────────────────────────────────────────┘
```

```java
public Product findById(Integer id) {
    String sql = "SELECT * FROM products WHERE id = ?";
    
    try (Connection conn = DBUtil.getConnection();
         PreparedStatement pstmt = conn.prepareStatement(sql)) {
        
        pstmt.setInt(1, id);

                product.setId(rs.getInt("id"));
                product.setName(rs.getString("name"));
                product.setPrice(rs.getBigDecimal("price"));
                product.setStock(rs.getInt("stock"));
                return product;
            }
        }
    } catch (SQLException e) {
        e.printStackTrace();
    }
    return null;
}
```

**插入操作（INSERT）：**

```java
public int insert(Product product) {
    String sql = "INSERT INTO products (name, price, stock, description, image_url) VALUES (?, ?, ?, ?, ?)";
    
    try (Connection conn = DBUtil.getConnection();
         PreparedStatement pstmt = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
        
        pstmt.setString(1, product.getName());
        pstmt.setBigDecimal(2, product.getPrice());
        pstmt.setInt(3, product.getStock());
        pstmt.setString(4, product.getDescription());
        pstmt.setString(5, product.getImageUrl());
        
        int affectedRows = pstmt.executeUpdate();
        
        // 获取自增 ID
        if (affectedRows > 0) {
            try (ResultSet rs = pstmt.getGeneratedKeys()) {
                if (rs.next()) {
                    return rs.getInt(1);  // 返回自增 ID
                }
            }
        }
    } catch (SQLException e) {
        e.printStackTrace();
    }
    return -1;
}
```

#### 2.1.3 computed 计算属性

**基本使用：**

```javascript
setup() {
    const cartItems = ref([
        { product: { price: 10 }, quantity: 2 },
        { product: { price: 20 }, quantity: 1 }
    ]);
    
    // 计算属性：根据响应式数据自动计算
    const cartCount = computed(() => cartItems.value.length);
    
    const cartTotal = computed(() => {
        // reduce 表示将两个值"缩减"为单个值
        return cartItems.value.reduce((sum, item) => {
            return sum + (item.product.price * item.quantity);
        }, 0);  // 0 是初始值
    });
    
    return { cartItems, cartCount, cartTotal };
}
```

**reduce 方法详解：**

```javascript
// reduce 的工作原理
const numbers = [1, 2, 3, 4];
const sum = numbers.reduce((accumulator, currentValue) => {
    return accumulator + currentValue;
}, 0);

// 执行过程：
// 1. 初始值: accumulator = 0
// 2. 第一次: accumulator = 0 + 1 = 1
// 3. 第二次: accumulator = 1 + 2 = 3
// 4. 第三次: accumulator = 3 + 3 = 6
// 5. 第四次: accumulator = 6 + 4 = 10
// 结果: 10
```

### 2.4 localStorage 本地存储

#### 2.4.1 localStorage 特性

**存储生命周期：**

```
localStorage > Application > Session > Cookie > Request > Page
```

**特点：**

- 存储在浏览器本地，关闭服务器不会清除
- 只要用户不清除或手动清理，数据永久保存
- 存储容量：约 5MB
- 只能存储字符串

**应用场景：**

- 用户登录状态持久化

### 3.1 SPA 单页面应用

#### 3.1.1 SPA 概念

**传统多页面应用：**

```
用户操作 → 页面跳转 → 服务器渲染 → 返回新页面
```

**SPA 单页面应用：**

```
用户操作 → JavaScript 更新 DOM → 无页面刷新
```

**优势：**

- ✅ 用户体验流畅，无刷新感
- ✅ 前后端分离，并行开发
- ✅ 局部更新，减少服务器负载
- ✅ 组件化开发，代码复用性高

```java
@WebServlet("/api/user/*")
public class UserServlet extends HttpServlet {
    private UserService userService = new UserService();
    
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        // 1. 读取请求体
        BufferedReader reader = request.getReader();
        StringBuilder sb = new StringBuilder();
        String line;
        while ((line = reader.readLine()) != null) {
            sb.append(line);
        }
        
        // 2. 解析 JSON
        Gson gson = new Gson();
        Map<String, Object> data = gson.fromJson(sb.toString(), Map.class);
        String phone = (String) data.get("phone");
        
        // 3. 调用 Service 处理业务
        User user = userService.register(phone);
        
        // 4. 返回响应
        if (user != null) {
            response.getWriter().write(JsonUtil.success(user));
        } else {
            response.getWriter().write(JsonUtil.error(400, "注册失败"));
        }
    }
}
```

```javascript
    // 回调函数: (累加器, 当前元素) => 返回新的累加值
    return cartItems.value.reduce((sum, item) => {
```

### 4.4 常见问题与解决方案

#### 1. 跨域问题

**问题：** 前后端分离时，浏览器报错 "No 'Access-Control-Allow-Origin' header"
**解决：** 在 Servlet 中添加响应头或配置 CORS 过滤器

#### 2. JSON 数字精度问题

**问题：** Java 后端返回的 Long 类型数字精度丢失
**解决：** 配置 Gson 将 Long 转为 String

#### 3. 异步请求错误处理

**问题：** 异步请求失败时用户体验不好
**解决：** 使用 try-catch + 统一错误提示

#### 4. localStorage 存储限制

**问题：** localStorage 只能存储字符串
**解决：** 使用 JSON.stringify() 和 JSON.parse() 存储对象
